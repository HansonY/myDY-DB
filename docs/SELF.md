# 第三层:了解自己

前两层是「把东西存下来」和「能找到」。这一层要回答的是另一类问题:

> 我为什么刷抖音?我以为我在看什么,实际在看什么?

## 立场:做落差,不做图表

分类饼图、时长柱状图谁都能做,看完你什么也没多知道 —— 因为你早就知道
自己爱看什么。**有价值的是落差**:你以为的和实际的不一样的地方。

所以这一层只出**对比**和**反直觉的发现**,每一条都必须能追到具体数据,
点得开、查得到。

---

## 一、现有数据已经能说的(下面数字都是实测)

### 1. 收藏 ≠ 点赞:「想学的」和「被吸引的」不是一回事

这是最有信息量的一刀。**收藏是「我打算之后再看」,点赞是「当下的情绪反应」**——
同一个人,两个动作,分类分布明显不同:

| 分类 | 收藏占比 | 点赞占比 | 落差 |
|---|---|---|---|
| 个人管理 | 19.4% | 15.7% | **+3.7 偏收藏** |
| 亲子 | 5.1% | 2.4% | **+2.7 偏收藏** |
| 医疗健康 | 4.6% | 2.7% | **+1.9 偏收藏** |
| 随拍 | 14.9% | 17.9% | −3.0 偏点赞 |
| 时政社会 | 4.7% | 10.3% | **−5.6 偏点赞** |

读法:自我管理 / 育儿 / 健康是**你想变成的样子**(存起来打算做);
时政 / 随拍是**当下真实的消费**(看完就算)。

另外「既收藏又点赞」139 条 —— 这批是两个动作都做了的,可以单独看,
大概率是真的在意。

### 2. 你是被推荐流喂的,不是自己搜的

三个指标同时指向这个结论:

```
中位赞数        收藏 3.6 万 · 点赞 3.9 万        —— 不是冷门内容
45% 落在 1-10 万赞区间                          —— 典型推荐流热度带
2115 个作者,90% 只出现过一次                    —— 完全不追人
前 50 个作者只占 11.9%                          —— 没有稳定关注对象
2023 年及更早的内容只占 1.4%                     —— 不回溯,跟着流走
```

而且**收藏和点赞的热度分布几乎重合**(中位 3.6 万 vs 3.9 万)。
如果收藏是主动搜来的,热度分布该更偏冷门 —— 没有。
**结论:你的收藏是「推荐流刷到,觉得有用就存」,不是「有需求去找」。**

### 3. 核心张力

把上面几条拼起来:

> 你在用一个为「即时消费」设计的推荐流,囤积「打算之后学」的内容 ——
> 而且是**中位 60 秒**的短视频形态(只有 14% 超过 5 分钟)。

这句话就是「为什么刷抖音」的雏形,而且每个词都有数据支撑,不是心理学套话。
接下来能量化的是**这个囤积有没有兑现**。

### 4. 囤积的规模

「收藏了却从没回来看」是最想知道的,但**抖音不给回看数据**,直接答不了。
能做的近似:用向量聚类算「同一主题囤了多少条」——
同一件事被反复吸引却存了 10 条,大概率一条都没消化完。

## 二、要新采才能做的:收藏时间

**「什么时候刷抖音」现在答不了。** 这是查出来的,不是猜的:

- `videos.collected_at` 是**我们抓取的时间**,只跨 3 天 —— 用它做时段分析是错的
- raw 里**没有**「你什么时候收藏它」这个字段(逐字段翻过)
- **但游标本身就是收藏时间戳**:
  ```
  collection  1783276199876512  微秒级 → 2026-07-06 02:29
  like        1780640956000     毫秒级 → 2026-06-05 14:29
  ```
  而我们只存了**页级**游标,没存每条的

所以:**每条的收藏时间只在采集当时能拿到**,和封面的 `x-expires` 一个道理 ——
不当场记就永久丢了。

### 改法

`videos` 加一列 `saved_at`。采集时按页括起来:第 N 页返回的游标是这一页
**最后一条**的收藏时间,所以这一页每条的收藏时间落在
`[cursor(N), cursor(N-1)]` 之间。一页 ~20 条,精度到几小时,
**对时段分析完全够用**。

实现:`_iter_pages` 已经在 yield `max_cursor` 了,`_persist_page` 顺手写进去即可。
存量数据要靠一次全量重走(refill 会经过每一页,顺带就能补)。

补上之后能做的:

- **时段指纹**:深夜刷的和白天刷的,分类分布差多少 ——
  情绪性消费 vs 目的性消费,这个落差大概率最刺眼
- **兴趣漂移**:半年前在囤什么,现在在囤什么
- **囤积节奏**:是均匀的,还是一阵一阵的(某几天狂存几十条 = 焦虑性囤积)
- **发布→收藏的时差**:秒收 = 推荐流当场存;隔月收 = 主动搜到的老内容

## 三、明确答不了的

诚实划清边界,比给一个含糊的数字重要:

| 想知道 | 为什么答不了 |
|---|---|
| 收藏了到底看没看 | 抖音不给回看记录。任何「你囤了没看」都只能是**推断**,必须标明 |
| 每天刷了多久 | 我们只能看到你**存下来的**,看过没存的完全不可见 |
| 是推荐来的还是搜来的 | raw 里没有来源字段。第 2 节那个结论是**多个指标的旁证**,不是直接证据 |
| 完播率 / 看了几遍 | 同上,平台不给 |

**这一层的每个结论都要标清是「实测」还是「推断」。** 一个听起来很懂你、
但其实是猜的画像,比没有画像更糟 —— 你会照着它调整自己。
这和检索层不编答案是同一条原则。

## 四、怎么做(实现)

```
backend/knowledge/insight.py      纯计算,只读库,无外部调用
  contrast()      收藏 vs 点赞 的分类落差
  sourcing()      热度分布 + 作者集中度 + 追新度 → 算法喂 vs 主动找
  hoarding()      向量聚类找主题,算每个主题囤了多少条
  timeline()      时段 / 漂移 / 节奏(依赖 saved_at,没有就明确返回「数据不足」)
  tension()       把上面几条拼成一句话结论 + 支撑数字

/api/insight                      一次算完,结果可缓存(数据不变就不用重算)
cli.py insight                    命令行看
MCP  library_insight              让 AI 拿着这些数据和你聊
```

**每个结论都带 `evidence`**:具体是哪些作品支撑的,前端能点开看列表。
不能只给一个百分比 —— 那和星座运势没区别。

### 前端

不做仪表盘。做**一页话 + 可展开的证据**:

```
你的收藏是「推荐流刷到觉得有用就存」,不是「有需求去找」   [看依据]
  ├ 中位赞 3.6 万,45% 在 1-10 万区间(推荐流热度带)
  ├ 2115 个作者,90% 只出现一次 —— 不追人
  └ 2023 年及更早只占 1.4% —— 不回溯

你想学的和实际被吸引的不一样                              [看依据]
  ├ 偏收藏:个人管理 +3.7 · 亲子 +2.7 · 医疗健康 +1.9
  └ 偏点赞:时政社会 −5.6 · 随拍 −3.0
```

MCP 那一路是这层的最佳形态 —— 你可以直接追问「那我该取消收藏哪些」,
AI 拿着 `library_insight` 的数据和你聊,而不是只看一张图。

## 五、顺序

| 步 | 做什么 | 依赖 |
|---|---|---|
| 1 | `insight.contrast()` + `sourcing()` + `tension()` | 无,现有数据够 |
| 2 | 一页话 + 可展开证据的界面 | 步 1 |
| 3 | `saved_at` 列 + 采集时按页括时间 | 无 |
| 4 | 全量重走补 `saved_at`(和 refill 合并跑) | 步 3 · 会碰抖音接口,有 403 风险 |
| 5 | `timeline()` 时段 / 漂移 / 节奏 | 步 4 |
| 6 | `hoarding()` 向量聚类找囤积主题 | 向量索引(已有) |

**步 1、2、6 全程不碰抖音接口**,可以随便重跑。只有步 4 要采集。

## 六、一个必须先说的数据缺口

上面所有分类相关的数字,分母都只是**有官方分类的 1753 条**,
而库里还有 **771 条「未采全」** 没有分类。补齐之后比例会变。

所以这一层的第一版应该**把分母写在脸上**(「基于 1753/2554 条」),
而不是给一个看起来很确定的百分比。
