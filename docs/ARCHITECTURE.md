# 架构

这份是**当前状态**,不是计划。有疑问以代码和实测数字为准。

---

## 一句话

把你自己的抖音(收藏 / 点赞 / 你发的 / 你关注的人)抓到本机,变成
**可搜、可问的知识库 + 每日情报站**。全程自部署,cookie 不出本机。

---

## 三层,只有最底下那层不可再生

```
L0  抖音接口 ──f2──► videos.raw_z        完整原始响应(zlib,4.9×)
    │                重采冒 403、媒体地址会过期 —— 丢了就真没了
    │
    │  ⚠️ 两种来源必须分开(store.mine_pred 是唯一判据):
    │     mine      我主动收藏/点赞/自己发的
    │     following 从关注的博主主页抓来的
    │  混在一起会同时坏掉两件事:拿别人的产出算「我的偏好」;
    │  检索被博主的营销视频淹掉。
    ▼
L1  派生层(纯本地,零网络,随时可全量重建)
    ├─ transcripts   desc 文案 / summary 抖音总结 / asr 本地转写 / queries 大家都在搜
    ├─ extractions   章节大纲
    ├─ tags          话题标签
    └─ fragments     检索的最小单位(等粒度文本)
    ▼
L2  frag_vec (sqlite-vec)                bge-m3 · 1024 维 · KNN < 1ms
    │
    ├─► 检索   向量 KNN → 按作品折叠 → 三档(0.64 / 0.52)
    │     └─► 问答   组上下文 → qwen-plus → **强制校验出处**,没依据不调模型
    ├─► 认识自己   兴趣主题 / 想学vs在看 / 干货率 / 关注缺口
    └─► 情报      每日简报(信息价值博主)· 竞品打法(对比上期)
```

**L1/L2 全可重建**,所以分块策略、嵌入模型、阈值随时能改。
**L0 一个字段都不能丢** —— 这就是 raw 压缩但不剪枝的根据。

## 用了哪些模型

| 用途 | 模型 | 在哪跑 | 要 Key 吗 |
|---|---|---|---|
| 向量检索 | **bge-m3**(1024 维) | 本机 | 不要 |
| 语音转写 | **faster-whisper large-v3-turbo** | 本机 | 不要 |
| 问答 / AI 画像 | **通义千问 qwen-plus** | 阿里云 | 要 `DASHSCOPE_API_KEY` |

**检索和转写完全离线**,不配任何 Key 也能用。只有「问答」和「AI 画像」
需要千问 —— 没配就如实空着,不编。

选型都是实测定的:
- bge-m3 是四个候选里**唯一真能中英互通**的(8 组话题命中 4,其余 0–1)
- ASR 从 small 换成 large-v3-turbo:small 的中文基本不能用
  (「打开雷达刺控管…」原视频讲微波炉);日常量只有每 3 天 11 分钟音频,
  速度不是约束,准确度才是
- qwen-plus 而不是带慢思考的型号 —— 后者会挂到分钟级

## 四个页面 + 一个维护页

| 页面 | 干什么 |
|---|---|
| **浏览** `/` | 卡片网格 · 字面搜 / 语义搜 · 按来源、可信度、话题筛选 |
| **认识自己** `/insight.html` | 兴趣球(可点)· 四张结论卡 · 右侧常驻问答 |
| **每日简报** `/digest.html` | 有价值博主这几天讲了什么 · 按方面分组 |
| **竞品** `/rival.html` | 竞品打法,每个数字对比上一个同长度周期 |
| 维护 `/data.html` | 设置(Key)· 采集 · 补齐 · 转写 · 索引 |

导航是**固定外壳**(整页不滚,内容区自己滚),所以导航栏一直在。

### 内容可信度是刚性概念

界面上到处都有这三档,颜色是语义不是装饰:

| | 是什么 | 覆盖 |
|---|---|---|
| 🔵 抖音总结 | 平台自己生成的内容总结 | ~34% |
| 🟣 本地转写 | 我用 whisper 转的逐字稿 | 按需补 |
| 🟠 只有文案 | **其实什么内容都没有**,常是营销话术 | 其余 |

混在一起展示等于骗自己 —— 所以「只有文案」的条目在简报里整块暖色底,
并直说「这条目前等于没有内容」,再给一个转写按钮。

## 抓关注的博主:只抓最近,不刨历史

每个博主两条水位线:

```
picked_at   第一次标成 有价值/竞品 的时刻 = 抓取起点(之前的老作品不抓)
fetched_at  上次抓完的时刻,下次从这里往后接着抓
```

抓取截止点 = `min(now - days, fetched_at ?? picked_at)`。
水位线记的是**这轮开始**的时刻而不是结束时刻 —— 记结束时刻会让抓取过程中
新发的作品永久跳过。

为什么不刨历史(这是走过的弯路):

| | 全量深挖(已删) | 每天最近三天 |
|---|---|---|
| 一次 | 4345 条 / 221 页 | 约 9 条 / 11 页 |
| 耗时 | 29 分钟,**第 20 页就 403** | 1.5 分钟,零风险 |
| 拿到 | 陈年老作品 | 今天他们讲了什么 |

## 模块与依赖方向

```
backend/
  collector/       唯一碰抖音的地方(f2 封装 + 从 787 字段真实响应提取)
  service.py       采集编排:逐页落库 + 水位线 + 跨进程锁 + 主动收手
  planner.py       每类决定 续采/增量/跳过 + 403 指数退避
  db/store.py      存取层 + raw 压缩(对上层透明)+ mine_pred 来源判据
  knowledge/       知识库,**不认识 collector**
    fragments.py   散字段 → 等粒度片段(纯函数)
    embed.py       文本↔向量(本地 bge-m3 / 云端可切)
    vecdb.py       唯一碰 sqlite-vec 的地方 + 指纹校验
    search.py      KNN → 折叠 → 三档 · scope 默认 mine
    answer.py      组上下文 → qwen → 出处校验(纯函数可离线测)
    asr.py         下音轨/视频 → whisper → 逐字稿 → 重建片段
    insight.py     兴趣主题 / 落差 / 干货率 / 关注缺口
    digest.py      每日简报 + 竞品报告
  main.py          HTTP(48 个接口)
  mcp_server.py    MCP(19 个工具)
```

依赖单向:`collector → config`,`knowledge → db + embed`(**不认识 collector**),
`service` 是唯一同时认识两边的。所以知识库这一侧永远不碰抖音接口 ——
没有 403 风险,可以随便重跑。

f2 **必须延迟导入**:它在 import 时就请求 mssdk 取 msToken,网络一抖
整个后端连导入都失败,会把纯本地的检索/分析一起拖垮。

## 三个防静默出错的设计

这类 bug 最难查 —— 不报错,只是结果悄悄变错。

1. **`vec_meta` 记模型名。** 维度不符 sqlite-vec 会报错,但**同维度不同模型不会**
   (bge-m3 和 Qwen3-Embedding-0.6B 都是 1024 维)。换模型不重建索引,
   查询照跑、结果全是垃圾且看不出来 → 检索前比对指纹,不符直接拒绝。

2. **`content_state` 三态而非布尔。** `have` / `none`(平台确认没给)/
   `unknown`(还没采全)。用 0/1 会把后两者混成同一个 0,而前者该认命、
   后者该去补采。落库时**只升不降**。

3. **孤儿向量清理。** `fragments` 是先删后插重建的,rowid 会变 → 旧向量指向
   不存在的片段,**会被检索到却对不上原文**。sync 每次清理。

## 硬约束

- **cookie = 账号控制权**:只存本机 `.env`(0600),不上传、不外发、不打印
- **只读**:绝不评论、点赞、关注 —— 批量写操作是封号主因
- **403 是常态**:断点续跑、主动收手、一个博主被拒就整体停
- **私有内容本地处理**:分析、转写、embedding 全在本机
