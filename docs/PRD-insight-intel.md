# Douyin-DB 产品需求 —— 认识自己 & 情报

> 给设计用。描述「要什么、为什么、能用什么料」,不规定具体布局 —— 布局交给设计。

---

## 0. 产品一句话

把**我自己的抖音**(收藏 / 点赞 / 我发的 / 我关注的人)抓到本地,变成一个
**个人知识库 + 情报站**。单人自部署,只有我一个人用。

---

## 1. 三个核心需求

| | 需求 | 现状 |
|---|---|---|
| ① | 爬来的数据能**浏览、能搜索** | 差不多了,本轮不重做 |
| ② | **分析我自己** | 要重新设计 |
| ③ | 把我跟的博主当**信息情报** | 要重新设计 |

本文档只详述 ② 和 ③。① 作为背景:它是一个能按分类/作者/来源筛选、
能字面搜也能语义搜的收藏浏览器。

---

## 2. 需求 ②:认识自己

### 目标
回答一个问题:**我存的这些东西,说明我是个什么样的人?**

### 硬要求
- 每个分析都要给「**结论 + 所以呢**」,不能只甩一个数字。
  反例:「你有 2556 条收藏」——无意义。
  正例:「你收藏全是学习类,点赞全是娱乐类 —— 你想学的和实际在看的不是一回事」。
- 只分析「**我主动选的**」(收藏 / 点赞 / 我发的),不能把爬来的博主内容算进去,
  否则等于拿别人的产出算我的偏好。

### 可用的分析素材(已经算好,直接用)
| 素材 | 是什么 | 信息量 |
|---|---|---|
| **想学 vs 被吸引** | 收藏 和 点赞 的分类分布落差 | 最高:理想 vs 实际 |
| 分类构成 | 我的收藏都是些什么类目 | 中 |
| 干货率 | 每个标签下,真有内容的比例 | 高:哪些是干货、哪些只是刷 |
| 兴趣漂移 | 兴趣随时间的变化(月级精度) | 中 |
| 消费形态 | 我能看完多长的视频 | 中 |
| 标签关系 | 哪些兴趣总是一起出现(共现网络) | 视觉化好看,当佐证 |

### 还要能做
- **问我自己**:基于我的收藏提问(「我为什么老收藏不看?」),答案**带出处**
  (哪条视频、第几秒),没依据就说没有、不许编。

### 精度约束(别设计做不到的东西)
- 时间只到**月级**(抖音不给收藏的精确时间,只能从翻页游标推)。
  能做「这个月 vs 上个月的兴趣变化」,**做不了**「我几点刷抖音」。

## 3. 需求 ③:情报

### 目标
**每天知道我跟的博主发了什么**,以及竞品在怎么打。不是把他们的历史全爬下来。

### 两类情报源,用法完全不同
| 类型 | 我要的是 | 呈现重点 |
|---|---|---|
| **信息价值博主** | 他讲的**内容** | 每条讲了什么(进知识库、可搜可问) |
| **竞品博主** | 他的**打法** | 选题 / 时长 / 发布节奏 / 互动,且**对比上期** |

### 硬要求
- **情报源要能挑、能分类**:我关注了 97 位,但只跟我选中的那几位。
  从关注列表里选人 + 打标「信息价值 / 竞品」。没打标的一律不抓、不显示。
- **只抓最近 N 天**(默认 3 天),按发布时间往前,遇到超过 N 天的就停。
  不做全量历史深挖(那要几小时、会被限流、拿回来还全是旧的)。
- **内容有三种可信度,必须一眼分清**:
  1. 抖音自己生成的内容总结(约 1/3 的作品有)
  2. 我本地转写的逐字稿(补上没总结的)
  3. 只有作者文案 = **其实什么内容都没有**,常是营销话术
  三者混在一起展示 = 骗自己。「只有文案」的必须标出来。
- **没内容的能一键补**:对没总结的作品本地跑语音转写(不联网问第三方)。

### 竞品打法要有对照
- 每个数字都配「**上一个同长度周期**」的对比。
  「这三天发了 5 条」没意义,「比上三天多 2 条」才有意义。

## 4. 全站体验要求(这是「乱」的根源,重点)

1. **统一导航**:每页都有同一条导航,任何时候知道「我在哪、还能去哪」。
2. **导航 ≠ 操作**:换页的链接,和「向抖音发请求(可能触发封号)」的按钮,
   **视觉上必须分开**。现在它俩长一样,是最大的问题。
3. **危险/耗时操作集中**:采集、补齐、转写这些,收到一个不起眼的维护入口里,
   不和日常浏览/看简报混在一起。
4. **说人话**:界面上不能出现 `following`、`content_state` 这种数据库字段名。

## 5. 数据家底(设计能用到的真实数据)

| 数据 | 量 / 覆盖 |
|---|---|
| 我的作品(收藏/点赞/我发的) | 2556 条,完整原始响应 |
| 我关注的人 | 97 位 |
| 官方三级分类 | ~98% |
| 抖音内容总结 | ~34%(其余靠本地转写补) |
| 语义检索 | 本地向量(中英都支持),换句话说也能搜到 |
| 收藏时间 | 月级精度 |
| 互动数据 | 赞/评/藏/转,判断「这条好不好」的唯一客观信号 |

---

## 6. 硬约束(不能碰)

- **cookie = 账号控制权**:只存本地,绝不上传、不外发、不打印。
- **只读**:绝不评论、点赞、关注 —— 批量写操作是封号主因。这是铁律。
- **采集有 403 风险**:必须能断点续跑、能主动收手,一个博主被拒就整体停。
- **私有内容本地处理**:分析、转写、embedding 全在本地,不发给第三方服务。

## 7. 现有技术接口(设计不用管实现,但可参考已具备的能力)

**② 认识自己** —— 后端分析全部就绪:
`GET /api/insight`(结论)、`/api/insight/graph`(标签图)、
`/api/insight/quality`(干货率)、`/api/insight/history`(漂移)。
问答走 `/api/ask`。MCP 侧缺一个「认识自己」工具,待补。

**③ 情报** —— 后端全部就绪:
`GET /api/digest`(两类简报)、`POST /api/digest/refresh`(抓最近N天)、
`GET /api/following` + `POST /api/following/role`(选人打标)。
MCP:`daily_digest` / `creators` / `set_creator_role` / `collect_recent` / `transcribe`。
