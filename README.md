# Douyin-DB

把你自己的抖音 —— **收藏、点赞、你发的、你关注的人** —— 抓到本机,
变成可搜、可提问的知识库,外加一份每天更新的情报简报。

> Your own Douyin (TikTok China) data, as a searchable self-hosted knowledge base.
> Everything runs on your machine — your cookie never leaves it.

**完全自部署**。数据和登录态只在你自己的机器上,项目方不接触,也没有服务器可以接触。

---

## 三步跑起来

```bash
./setup.sh     # 装依赖(Python 3.10–3.13)
./go.sh        # 扫码登录 + 采集(可反复跑,断点续跑)
./web.sh       # 打开 http://localhost:8000
```

就这些。`go.sh` 首次会开浏览器让你扫码,之后直接采;被抖音限流会自己退避,
下次接着走,不会重头再来。

**不想装任何 Key 也能用** —— 检索和语音转写全在本机跑。
只有「AI 问答」和「AI 画像」要配通义千问的 Key,在网页的**维护 → 设置**里填。

## 打开之后看什么

| | |
|---|---|
| **浏览** | 所有抓来的内容。字面搜、也能「换句话说」语义搜 |
| **认识自己** | 我的收藏说明我是什么人。可点的兴趣球 + 结论卡 + 常驻问答 |
| **每日简报** | 我跟的博主这几天讲了什么 |
| **竞品** | 竞品的打法,每个数字对比上一个同长度周期 |
| 维护 | 设置 Key、采集、补内容、转写 |

**先去「维护」把你关注的人同步下来,挑几个标成「有价值」或「竞品」** ——
简报和竞品页才有东西看。97 个关注里通常只有十来个值得跟。

## 内容有三档可信度,界面上一眼分得清

| | 是什么 |
|---|---|
| 🔵 抖音总结 | 平台自己生成的内容总结(约 1/3 的作品有) |
| 🟣 本地转写 | 你用 whisper 转出来的逐字稿 |
| 🟠 只有文案 | **其实什么内容都没有**,只是作者写的标题,常是营销话术 |

抖音**不给字幕文本**(逐个字段翻过两遍,只有一个 `is_subtitled` 标记),
所以那 2/3 要靠本地转写补 —— 在维护页或简报里一键加入队列,
全程在本机跑,不发给任何第三方。

## 给 AI 用(MCP)

19 个工具,第三方 AI 应用(Claude Desktop 等)可以直接查你的库:

```
about_me            我是个什么样的人(兴趣主题 / 想学vs在看 / 干货率 / 关注缺口)
search_library      语义检索 —— 换句话说也找得到
ask_library         基于收藏回答,强制带出处,没依据就说没有
daily_digest        我跟的博主这几天讲了什么
creators            关注名单 + 我存过他几条
set_creator_role    把某人标成 有价值 / 竞品
collect_recent      抓最近 N 天的新作品
transcribe          本地转写补内容
…还有采集状态、原始响应、库统计等
```

配置方式见 [docs/MCP.md](docs/MCP.md)。

---

## 会不会封号

设计上**只读**:绝不评论、点赞、关注 —— 批量写操作才是封号主因。

采集会被 403 限流,这是常态不是故障。程序的应对是:逐页落库 + 逐页存进度、
指数退避、主动收手(宁可少采几页也不硬撞)、一个博主被拒就整体停手。
任何时候中断都能接着来。

## 需要什么

- Python 3.10–3.13
- 你自己的抖音 cookie(扫码登录时自动写入本机 `.env`,权限 0600)
- 可选:通义千问 API Key —— 只影响 AI 问答和画像
